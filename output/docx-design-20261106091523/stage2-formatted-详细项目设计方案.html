执行摘要

本方案是《需求定义文档》的下游设计文档，将 R1—R6 六项需求落成可实施的工程技术设计：四层总体架构（接入层 / 业务层 / AI 层 / 数据层），七大业务数据表与领域状态机，十个 Agent 工具与五轮上限的编排 Harness，BM25+向量混合检索的知识问答，以及"AI 起草、人工核定"的 HITL 机制。实施按首期 3 个月试点排布四个里程碑，测试评估与《需求定义文档》的 AC-01～AC-10 验收标准逐条衔接。

设计基准：本方案与已实现的 MVP 代码库（FastAPI + SQLAlchemy 异步 + aiosqlite，Agent 编排与 RAG 已具备）对齐，设计描述即实现现状的可验证表达；试点推广阶段的扩展项以"（扩展）"标注。

一、设计目标与范围

设计目标：以最小可用产品承载 P0 三项需求（版本分发与交底触达 R1、变更台账与状态机 R2、AI 辅助签证起草 R3），同时为 P1（制度问答 R4）与 P2（读图找差异 R5、管理看板 R6）预留扩展点。设计范围不含业主侧系统改造与电子签章集成（另行立项）。

设计原则说明
版本唯一可信源一切以变更台账为准，旧版本自动作废，杜绝多版本并行
授权链强制完整无书面依据的变更单不可进入待签证状态（对应 AC-02）
AI 辅助不越权AI 起草/建议不落终态，关键动作人工审批，全程留痕可追溯
可评测可回滚30 条评测用例回归 + 上线检查清单五维度，异常可 30 分钟回滚

二、总体架构

层组成职责
接入层Web 前端（工作台/变更台账/交底中心/签证协同/看板/管理后台）、登录鉴权角色化入口，演示账号一键体验，FDE 风格界面
业务层FastAPI 路由：auth / chat(SSE) / expenses / knowledge / admin / construction认证、对话、报销辅助、知识库、后台管理、变更与签证领域接口
AI 层Agent Harness（10 工具，5 轮上限）、RAG 混合检索、HITL 中断恢复制度问答、状态查询、AI 起草签证、费用校验，决策日志留痕
数据层SQLAlchemy 异步模型 + SQLite（生产可切 PostgreSQL）、文件存储（制度文档/图片）七类业务表 + 决策日志表，seed 演示数据

外部依赖：DeepSeek 大模型 API（对话与起草生成）；无向量化能力时 RAG 自动降级为纯 BM25 中文 bigram 检索，保证功能不中断。（扩展）图纸比对服务作为独立worker接入，不阻塞主链路。

三、功能模块设计

3.1 需求到模块的映射

需求模块关键设计
R1交底中心变更发布生成带版本号交底单；干系人推送；签收留痕（人/时间/版本）；AI 摘要变更要点
R2变更台账状态机：在建→交底中→待签证→已确认；新版本创建后旧版自动作废；按项目/状态筛选
R3签证协同AI 起草签证单草稿→待核定→人工核定→待确认→已生效/驳回；驳回可改后重提

R6看板处理时长/返工/采用率/复核成本统计，按月报表

3.2 Agent 工具集（10 个）

工具类别说明
search_policy / get_expense_standard知识检索制度检索（BM25+FAISS 混合、RRF 融合）与费用标准查询
validate_expense校验报销费用合规校验（限额/票据/日期规则）

draft_visa签证领域AI 起草签证单：仅生成"待核定"草稿，人工核定后流转

3.3 编排与 HITL

Harness 以 5 轮为上限逐步调用工具并汇总答案；每一步写入决策日志表（agent_step_logs）可回放审计。涉及提交类动作时进入 HITL 中断：系统生成确认请求（confirm_request 事件），用户确认后从快照恢复执行，拒绝则终止并记录。该机制同时满足"AI 不自动批准、不直写业务系统"两条红线。

五、AI 能力设计

5.1 RAG 检索问答

文档切分后建立 BM25（中文 bigram）与向量（FAISS）双路索引，检索结果以 RRF 融合重排；答案强制携带出处章节号，检索不到时明确告知并引导人工查阅（AC-09）。DeepSeek 不提供向量化时自动降级纯 BM25，功能可用性优先。

5.2 起草生成

签证起草提示词限定：只依据变更单事实字段生成草稿，缺失字段留空标注"待补充"，不得编造工程量与金额；输出直接落"待核定"状态，等人工核定。

5.3 评测体系

30 条评测用例覆盖四类：制度问答（含 3 个陷阱题）、工具调用、违规意图、多轮上下文；每次 prompt 或工具变更后全量回归，作为 AC-07 的证据来源。

六、接口与权限设计

接口组要点
/api/auth（register/login/me）JWT 签发与身份查询；密码哈希存储
/api/chat（SSE）事件流：status/sources/delta/expense/tool_call/tool_result/confirm_request/done/error
/api/construction项目/变更/版本/交底/签证 CRUD 与状态流转；授权链完整性校验拦截
/api/knowledge / /api/admin知识库管理与后台运营（上传/列表/统计）

权限模型：按角色授权（管理员/造价/施工员/质量安全/业主代表）；质量安全角色对红线事项持一票否决；未授权数据不参与检索；所有写操作留操作日志。

七、非功能设计

- 性能：检索问答 P95 ≤ 5 秒（降级 BM25 后 P95 ≤ 2 秒）；SSE 首字延迟 ≤ 3 秒；（扩展）并发限流按用户维度令牌桶；

- 安全：JWT 过期与刷新、SQL 参数化、上传文件类型白名单、密钥仅存环境变量不入库；

- 可用性：异常兜底（模型超时返回降级提示）、冒烟测试 8 项常驻；

- 可回滚：版本化部署 + 数据库迁移脚本回滚；上线检查清单五维度（数据安全/并发限流/异常兜底/内容安全/回滚预案）作为发布门禁；

- 可观测：决策日志 + 指标埋点（问答命中率、起草采纳率、确认时长），支撑 R6 看板取数。

九、测试评估与验收衔接

测试分层：单元（模型与工具函数）、接口（冒烟 8 项）、评测（30 条回归）、UAT（按 AC 清单逐条演示）。所有验收证据（评测报告、签收留痕、决策日志、月报）归档至项目文档目录，供顾明岚（业务负责人）与傅景（红线审批人）联签确认。上线前完成一次真实单据链的端到端回归，替代合成样本口径。
