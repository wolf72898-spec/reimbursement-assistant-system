# 项目简报 ②：需求清单与访谈事实

> 实验室机会阶段输出的业务需求条目（含优先级与证据编号）

## 1. 工程变更与签证协同：明确业务目标与试点条件
- **责任角色**：项目经理　**状态**：已完成角色事实采集，仍需试点验证　**优先级**：P1
- 证据 [construction-change-f00]：变更确认平均 12 天，目标 6 天；返工损失每月 45 万元目标减少 30%
- 证据 [construction-change-f01]：当前主流程是：现场问题 → 设计澄清 → 变更审批 → 施工交底 → 签证计量 → 结算。管理层还没有分别量出每个节点的等待和处理时间。
- 证据 [construction-change-f02]：一个施工分区试点，版本错误提示召回 100%，签证依据完整率 95%
- 证据 [construction-change-f03]：首期可用预算 20 万元，包含集成、培训与验证。收益要扣除维护及人工复核成本，不能把全部节省工时当作现金回款。
- 证据 [construction-change-f04]：立项由项目经理推动；质量安全负责人可以因关键风险否决上线，业主项目代表参与服务结果验收。
- 证据 [construction-change-f05]：版本核对与变更追踪，不代签设计或合同文件。首期采用历史资料回放，再做小范围并行试点，不直接替换现有业务。

## 2. 工程变更与签证协同：一线异常与操作辅助
- **责任角色**：现场施工员　**状态**：已完成角色事实采集，仍需试点验证　**优先级**：P1
- 证据 [construction-change-f10]：现场拿到旧图施工，设计新图已上传但没人做交底
- 证据 [construction-change-f12]：每月 85 个变更，核对图纸与签字每项约 90 分钟
- 证据 [construction-change-f11]：口头要求增加管线，事后签证被拒，无法确认授权链
- 证据 [construction-change-f15]：建议必须显示对应原记录和待确认字段。发生“口头要求增加管线，事后签证被拒，无法确认授权链”时，我会暂停该建议，由造价工程师核对后继续，错误结果不能覆盖原记录。
- 证据 [construction-change-f13]：现场执行围绕“工程变更与签证协同”。高峰期只能使用现有终端，离开业务现场去补录会延误处理；草稿应可暂存，并明确最后同步时间。
- 证据 [construction-change-f14]：因为“现场拿到旧图施工，设计新图已上传但没人做交底”，同事经常把关键说明留在个人便签或群里，再补进正式记录；这些说明目前没有随单据交接。

## 3. 工程变更与签证协同：流程规则与责任交接
- **责任角色**：造价工程师　**状态**：已完成角色事实采集，仍需试点验证　**优先级**：P0
- 证据 [construction-change-f22]：我的岗位是造价工程师，可以整理、校核和发起复核；不能代替质量安全负责人完成专业签核，也不能自行批准“版本核对与变更追踪，不代签设计或合同文件”以外操作。
- 证据 [construction-change-f24]：与“工程变更与签证协同”相关规则由业务负责人维护，按生效日期和适用范围选版本。规则冲突时附两个版本给质量安全负责人，不自行合并或选较宽松条款。
- 证据 [construction-change-f20]：现场问题 → 设计澄清 → 变更审批 → 施工交底 → 签证计量 → 结算。我负责把每一步的输入、输出和待办责任人写清楚；退回原步骤必须保留原因。
- 证据 [construction-change-f23]：交接至少包含业务编号、当前版本、处理状态、未解决事项和接手人。对方确认接手才结束本岗待办，仅发送消息不算完成。
- 证据 [construction-change-f21]：图纸版本、设计回复、签证、工程量清单与会议纪要
- 证据 [construction-change-f25]：异常先由造价工程师分派给实际处理人；超过约定时限再升级到项目经理。跨岗问题不能只写“已转交”，需要明确下一责任人。

## 4. 工程变更与签证协同：数据口径与接口治理
- **责任角色**：工程平台工程师　**状态**：已完成角色事实采集，仍需试点验证　**优先级**：P1
- 证据 [construction-change-f31]：图纸编码不统一，签证发生日与确认日混用
- 证据 [construction-change-f33]：先校验“图纸版本、设计回复、签证、工程量清单与会议纪要”里的主编号、事件时间和版本字段。图纸编码不统一，签证发生日与确认日混用；有歧义的记录进入人工修复队列，不进入自动推荐样本。
- 证据 [construction-change-f30]：我们正在使用BIM 文档库、项目管理平台与造价软件，各系统账号权限独立维护，业务状态尚没有统一视图。
- 证据 [construction-change-f32]：可读文档与流程，不自动批准变更或签署工程量
- 证据 [construction-change-f34]：本次试点计划每天两次更新已授权的业务状态，原始资料按版本更新；信息超过一个更新周期就标为待刷新，不能作为实时承诺。
- 证据 [construction-change-f35]：接口中断时继续使用带时间戳的上一份只读快照，并显示“暂未更新”。重连后按业务编号去重补齐，不反复触发同一待办；现有人工流程继续运行。

## 5. 工程变更与签证协同：约束核验与人工兜底
- **责任角色**：质量安全负责人　**状态**：已完成角色事实采集，仍需试点验证　**优先级**：P0
- 证据 [construction-change-f41]：只有授权的业务岗位可以查看“图纸版本、设计回复、签证、工程量清单与会议纪要”。涉及最终决定、对外承诺或资产变更，要由对应审批人确认，不能借用其他人的账号。
- 证据 [construction-change-f44]：出现“口头要求增加管线，事后签证被拒，无法确认授权链”、资料缺少依据、两个版本冲突或关键系统不可用时转人工。需要标注触发原因、接手人和确认时间，不能只给一句模糊提醒。
- 证据 [construction-change-f40]：结构安全和设计变更必须由合格人员审核，本场景不做专业计算
- 证据 [construction-change-f42]：一个施工分区试点，版本错误提示召回 100%，签证依据完整率 95%；同时检查“结构安全和设计变更必须由合格人员审核，本场景不做专业计算”。只要触及停止条件，就暂停试点并由负责人复盘。
- 证据 [construction-change-f43]：试点原始资料按本场景授权范围保存；本轮评价记录暂保留 90 天，期满由质量安全负责人复核删除或归档。真实期限仍须按组织规则另行确定。
- 证据 [construction-change-f45]：每次建议保留业务编号、资料版本、事实引用、建议结果、人工改动和签核人。审计时应能重建“现场问题 → 设计澄清 → 变更审批 → 施工交底 → 签证计量 → 结算”中的这次处理，不记录账号口令或不必要的个人信息。

## 6. 工程变更与签证协同：服务解释与反馈闭环
- **责任角色**：业主项目代表　**状态**：已完成角色事实采集，仍需试点验证　**优先级**：P1
- 证据 [construction-change-f50]：现场按施工完成计量，造价按签证有效计量，业主按审批版核价
- 证据 [construction-change-f54]：客户或下游反馈优先关联原业务编号和当时使用的资料版本，再查实际交接是否完成。争议由业主项目代表受理、造价工程师核对，未经确认不承诺赔偿或结果。
- 证据 [construction-change-f51]：目前可用工作量基线是：每月 85 个变更，核对图纸与签字每项约 90 分钟。服务侧还会逐笔采集交接等待和重新联系次数，不能用发送通知数量代替实际完成量。
- 证据 [construction-change-f52]：版本核对与变更追踪，不代签设计或合同文件
- 证据 [construction-change-f53]：现场按施工完成计量，造价按签证有效计量，业主按审批版核价。需要分别记录各岗完成时间，试点指标固定分母、排除规则和统计周期，不能把同一业务拆成多次“成功”提高比例。
- 证据 [construction-change-f55]：试点每周收集 现场施工员、造价工程师、业主项目代表 的误判例子和未解决问题，由项目经理确认改进负责人；先复测“一个施工分区试点，版本错误提示召回 100%，签证依据完整率 95%”，再更新规则版本。
