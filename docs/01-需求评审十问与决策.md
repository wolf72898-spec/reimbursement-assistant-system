# 提示词1 · 需求评审：十个关键问题与决策

> 角色：十年经验的企業信息系统架构师 | 项目：报销助手智能体系统 | 目标用户：企业员工和管理员

每个问题都附有"不同答案 → 架构差异"的说明。决策按架构师推荐值锁定，⚠️ 标记的项可推翻重议。

---

## 问题 1：发票类型与录入方式

**问题**：支持哪些票据？仅增值税电子发票，还是含纸质票、火车票、打车票、餐饮票？员工是拍照上传、转发电子发票文件，还是自动导入？

**架构差异**：
- 只做增值税电子发票 → 走结构化解析（二维码/XML），成本极低，无需 OCR
- 混合票据 → 必须引入 OCR 识别服务（自研或第三方 API），架构上多出识别服务与人工复核环节

**决策**：一期支持电子发票 + 手工填写票据信息；OCR 二期 ⚠️

## 问题 2：AI 智能体的定位边界

**问题**：智能体是"辅助"还是"主体"？是聊天式引导填单 + 票据录入 + 政策问答，还是连智能审核（自动判断合规并给拒批理由）都做？

**架构差异**：
- 含智能审核决策 → 需 LLM 审核链路、审计留痕、"AI 建议 + 人工终审"兜底机制
- 纯辅助 → 规则引擎为主、LLM 为辅，架构简单很多；决定大模型是核心依赖还是可选组件

**决策**：AI 为核心依赖——政策问答（RAG）+ 对话式发起报销 + 字段自动抽取；智能审核二期

## 问题 3：报销制度复杂度

**问题**：单一公司一套制度，还是多主体（多法人/分公司/部门）差异化标准？

**架构差异**：
- 单一制度 → 校验逻辑可硬编码
- 多主体差异 → 必须做可配置规则引擎（科目、额度、生效日期全部数据化），否则每次改制度都要发版

**决策**：一期单公司一套制度，字段数据化存储，为配置化预留 ⚠️

## 问题 4：审批流程形态

**问题**：固定逐级审批，还是可配置的多级审批、金额分级、会签/或签、条件分支？

**架构差异**：
- 固定流程 → 简单状态机即可
- 可配置流程 → 引入工作流引擎（Flowable/Camunda）或自研流程配置器，是全系统复杂度最大的分水岭

**决策**：一期仅"提交 → 管理员查看"固定状态机；多级审批二期 ⚠️

## 问题 5：与现有系统的对接

**问题**：现有 ERP/OA/财务系统是什么（SAP、用友、金蝶、自研 OA）？报销结果要写凭证、生成付款单吗？

**架构差异**：
- 需对接 → 必须设计集成层（API 网关 + 主数据同步 + 可能的消息队列）
- 独立系统 → 先用 Excel/凭证文件导出过渡

**决策**：一期不对接，支持导出 Excel ⚠️

## 问题 6：打款方式

**问题**：报销款怎么付——财务手工打款、银企直连自动付款，还是随工资代发？

**架构差异**：
- 银企直连 → 银行接口对接、资金安全与对账模块，金融级要求
- 手工打款 → 系统止步于"生成付款汇总表"

**决策**：一期线下打款 ⚠️

## 问题 7：部署方案

**问题**：私有化（内网/自有服务器）、公有云 SaaS，还是混合？数据能否出内网？

**架构差异**：
- 私有化 → 放弃多租户、交付运维成本高、技术栈要迁就客户环境；且约束问题 2：数据不出内网时 LLM 只能选本地化模型
- SaaS → 从第一天做租户隔离设计

**决策**：私有化/内网优先，LLM 走云端 API（可换供应商）⚠️

## 问题 8：用户规模与并发

**问题**：多少员工使用？月末是否集中报销（如月底三天 80% 单量）？

**架构差异**：
- 百人级 → 单体 + 单库足够
- 千人级 + 潮汐 → 异步化（OCR/审核队列）、缓存、读写分离；但不建议一上来就微服务

**决策**：百人级，单体架构 + 单库

## 问题 9：数据安全与合规要求

**问题**：发票与财务数据的敏感等级？有没有等保（二级/三级）、审计留痕、数据保留年限的硬性要求？

**架构差异**：
- 等保三级 → 强制加密存储/传输、操作审计、权限最小化，影响数据库选型与部署环境
- 无硬性要求 → 基础 RBAC + 敏感字段加密起步

**决策**：一期 RBAC + JWT + 密码哈希 + 操作留痕；等保等级待确认 ⚠️

## 问题 10：终端形态

**问题**：员工在哪里提交报销——Web、小程序、企业微信/钉钉内嵌、App？审批人是否要求移动批单？

**架构差异**：
- 小程序/企微内嵌 → 决定前端技术栈、消息通知渠道、免登集成；移动审批几乎是刚需
- 纯 Web → 最快交付 MVP

**决策**：Web 端先行，API 设计不绑定终端，小程序二期 ⚠️

---

## 一页纸结论

**主轴三题**：AI 定位（核心依赖）、审批流程（一期状态机）、部署形态（内网优先）——它们的答案收敛了其余选型空间。

**一期验收口径**：员工登录 → 对话问制度（基于上传文档、标注出处）→ 对话式生成报销单草稿（缺字段自动追问）→ 管理员查看记录与制度维护。

**遗留决策点（需业务方拍板）**：① 等保等级 ② LLM 供应商预算 ③ 二期 OCR 与审批流范围。
