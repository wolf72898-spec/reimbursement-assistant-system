## 一、业务机会触发事件

**案例标题：一张变更单的三个版本**

| 项目要素 | 内容 |
| --- | --- |
| 业务对象 | 工程变更与签证协同 |
| 触发事件 | 现场拿到**旧版图纸**施工，设计院新版变更图**已上传平台**，但**无人做技术交底** |
| 直接后果 | 按旧图施工造成返工；变更签证单出现"三个版本"不一致（施工员、造价、业主口径各执一版） |
| 客户诉求 | 管理层希望用 AI 改善，但**未确定优先环节、验收标准和权限边界** |

**现状问题描述（客户开场原话）：**

> "我们在'工程变更与签证协同'上投入了很多人力。现场拿到旧图施工，设计新图已上传但没人做交底。管理层希望用 AI 改善，但还没有确定优先环节、验收标准和权限边界。请你先和各岗位聊聊，找出值得验证的业务需求。"

**如果维持现状，会产生什么损失？**

1. **返工损失直接计入项目成本**：图纸版本错位 → 已完工程拆改 → 材料与人工双重浪费；
2. **签证争议侵蚀利润**：变更单多版本不一致 → 造价核定拖延 → 结算争议、利润点流失；
3. **责任无法追溯**：交底缺失 + 纸质/分散记录 → 出现质量安全事故时责任划分不清；
4. **管理层决策盲区**：没有统一的处理时长、返工率指标 → 无法判断改善优先级与投入回报。

### 4.2 决策链与调查边界

- **谁承担结果**：顾明岚（项目经理）对试点 ROI 负责；
- **谁批准范围与数据访问**：顾明岚发起，傅景（质量安全）对权限与红线有一票否决权；
- **谁批准继续或停止**：阶段关卡由业务负责人（顾明岚）确认问题、指标口径与调查范围后进入下一阶段；
- **调查边界**：仅使用本项目合成资料；保留权限、异常与人工确认环节；不自动批准、不写入业务系统；
